# 00. 全体原則

## 1. 情報の原則
- **SSOT（Single Source of Truth）**: 1つの情報の正本は1か所。他の場所にはリンクだけ置く。
- **索引はここ、実体は各サービス**: このリポジトリは実データを持たず「どこにあるか」と「どうするか」を持つ。
- **秘密は書かない**: パスワード等はパスワードマネージャに置き、ここには保管場所名だけ書く。

## 2. 新しく何かを作るときのフロー
1. 該当ルール（`rules/`）を確認する。無ければ先にルールを決める（またはClaudeに案を出させる）。
2. ルールに従って作成・登録する。
3. `inventory/` に1行追記する。

## 3. 命名規則（共通）
- 小文字・ハイフン区切り（kebab-case）。例: `shop-amazon`, `finance-rakuten-bank`
- 用途カテゴリ（プレフィックス）は以下で統一する。メール・フォルダ・タグ等で共通利用。

| プレフィックス | 用途 |
|---|---|
| （なし） | 個人の主連絡先は `akihisa.onuki@bluemoment.fyi`（プレフィックス無し。[email.md](email.md)） |
| `family` | 家族・保育園・行政 |
| `work` | 仕事関連 |
| `finance` | 銀行・証券・カード・保険・税 |
| `shop` | EC・会員サービス |
| `dev` | 開発・GitHub・クラウド・ドメイン |
| `sub` | サブスク（動画・音楽・SaaS） |
| `news` | ニュースレター・メルマガ |
| `temp` | 一時利用（使い捨て） |
| `legacy` | 旧Gmailからの転送受け（移行期間のみ。例: `legacy-<旧アカウント名>`） |

## 4. 見直し
- 年1回（毎年1月）に `inventory/` を棚卸しし、使っていないサービスは解約・アカウント削除する。
